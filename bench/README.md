# Benchmarks

The method and the current results are summarised in
[docs/benchmarks.md](../docs/benchmarks.md); this file is the development log.

Numbers here are informal checks during development. Runs with KROWN's
own execution framework are in [krown/README.md](krown/README.md); none of
these numbers come from the environment the KROWN paper measured on
(Ubuntu 22.04, x86_64, Intel Xeon E5-2650 v2, 48 GB RAM).

## 2026-10-05 · CSV, one triples map, 6 quads per row

Machine: Apple M4, 16 GB, macOS. Each figure is the median of three runs,
measured with `/usr/bin/time -l` (wall time, maximum resident set size).
Morph-KGC 2.10.0 on Python 3.12, `number_of_processes=1`.

Data: `id,first,last,email,city,age`, generated by `gen_people.py`.
Mapping: subject template + `rml:class` + five predicate-object maps
(four references, one IRI template). Both engines produce the same quads
(compared after sorting; Morph-KGC writes two spaces before the final dot).

| Rows | Quads | RMLrs before streaming | RMLrs (streaming) | RMLrs (+ escaping fast path) | Morph-KGC 2.10.0 |
|---|---|---|---|---|---|
| 100,000 | 600,000 | 1.66 s, 541 MB | 0.72 s, 37 MB | **0.58 s, 37 MB** | 1.97 s, 275 MB |
| 1,000,000 | 6,000,000 | 10.98 s, 3,747 MB | 7.03 s, 275 MB | **5.70 s, 275 MB** | 9.53 s, 1,165 MB |

"Before streaming" read the whole source and collected every quad in a
sorted set before writing. "Streaming" reads CSV row by row, writes each
quad as soon as it exists, and keeps only a 128-bit fingerprint per
distinct quad for duplicate removal; that set is most of the 275 MB.

Escaping fast path: values without characters to escape are written in
one call, and terms are written straight to the output instead of through
a temporary string.

A faster hand-written fingerprint hash was also tried and **dropped**: it
cut another second but merged about 99,000 distinct quads at 1M rows,
which only showed up when the output was compared with Morph-KGC's.
`fingerprints_keep_similar_quads_apart` in the engine tests now catches
that hash (280,000 of 300,000 kept).

Reproduce:

```bash
python3 bench/gen_people.py /tmp/bench 1000000
cargo build --release -p rmlrs-cli
cd /tmp/bench && /usr/bin/time -l <repo>/target/release/rmlrs run mapping_1000000.ttl -o out.nq
```

## 2026-10-05 · KROWN scenarios (local, not the official harness)

Data and mappings from KROWN's data generator (`kg-construct/KROWN`
824438c, the Morph-KGC configurations). KROWN writes legacy R2RML/RML
mappings; `krown_to_rml.py` rewrites them to the current vocabulary for
RMLrs (the engine itself does not read the legacy vocabulary), and
Morph-KGC runs the original. Same machine and method as above; median of
three runs. Outputs compared after sorting: identical in every case.

| Scenario | Quads | RMLrs | Morph-KGC 2.10.0 |
|---|---|---|---|
| Joins, 1-1, 0% joined (100K × 20 columns, two sources) | 0 | 0.62 s, 59 MB | 1.31 s, 188 MB |
| Joins, 1-1, 50% joined | 50,000 | 0.66 s, 59 MB | 1.36 s, 214 MB |
| Joins, 1-1, 100% joined | 100,000 | 0.68 s, 60 MB | 1.40 s, 241 MB |
| Raw data, 100K members × 20 properties | 2,000,000 | 1.51 s, 139 MB | 4.72 s, 403 MB |
| Raw data, 1M members × 20 properties | 20,000,000 | 15.83 s, 1,091 MB | 40.18 s, 1,456 MB |

At 20M quads most of RMLrs's memory is the duplicate-removal fingerprint
set (16 bytes per distinct quad, plus hash-table growth). Not yet run:
10M members and the other KROWN scenarios (since run with KROWN's
framework). Runs with
KROWN's own execution framework (Docker, time/CPU/RAM sampling) are in
[krown/README.md](krown/README.md).

## 2026-10-06 · XML with XPath, one triples map, 2 quads per element

Same machine and method (median of three runs). Data: 100,000
`<person id="…"><name>…</name><age>…</age></person>` elements (6.9 MB).
Mapping: iterator `/people/person`, subject template `{@id}`, references
`name` and `age`. Outputs identical after sorting.

| Elements | Quads | RMLrs | Morph-KGC 2.10.0 |
|---|---|---|---|
| 100,000 | 200,000 | 1.09 s, 361 MB | 8.74 s, 535 MB |

XML is parsed into a tree (`xee-xpath`, XPath 3.1) because references may
walk up from an iteration (`../@id`), so memory grows with the document:
about 50 times the file size here. Streaming XML would need a restricted XPath subset;
see [ADR 0007](../docs/adr/0007-xpath-with-xee.md).

## 2026-10-09 · Memory: duplicate-removal set and XML sources

Same machine (Apple M4, 16 GB, macOS), `/usr/bin/time -l`, CLI run
directly. "Before" is `3a8fa52`, "after" the commit that adds this section.
Outputs are identical before and after (XML byte for byte; CSV after
sorting, and equal to Morph-KGC's).

| Case | Quads | Before | After |
|---|---|---|---|
| KROWN raw data, 1M members × 20 properties (CSV) | 20,000,000 | 16.39 s, 988 MB | 16.46 s, 435 MB |
| XML, 100,000 elements (6.9 MB) | 200,000 | 0.55 s, 345 MB | 0.48 s, 44 MB |

Before/after runs were interleaved, three each; the table shows medians.

- **Duplicate removal.** The `HashSet<u128>` of fingerprints became a set
  of its own (`crates/rmlrs-engine/src/dedup.rs`): 256 shards, linear
  probing, 12 bytes per slot, shards double when 3/4 full. Growing copies
  one shard, so the set never holds an old and a new full table at once.
  103 of the 128 fingerprint bits are kept (merging two distinct quads has
  a probability of about n² / 2¹⁰⁴).
  A first version with 4,096 shards that grew by a quarter at a time used
  *more* memory (1.4-1.5 GB): the freed smaller tables stayed with the
  allocator as holes it could not reuse. The variants tried, at 20M quads:
  64 shards doubling 482 MB, 64 growing by half 562 MB, 1,024 doubling
  540-581 MB, 4,096 doubling 753-778 MB, 256 doubling 434 MB.
- **XML.** When the iterator is a plain path of child steps (`/a/b/c`) and
  no reference of the logical source looks outside the iterated element,
  the document is cut into the selected elements (with the namespace
  declarations they inherit) and parsed 256 KB of elements at a time. Any
  reference such as `../@id` keeps the whole-document tree. The document
  text itself is still read into memory.
