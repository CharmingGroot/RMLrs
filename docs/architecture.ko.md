# 아키텍처

[English](architecture.md) | [한국어](architecture.ko.md)

## 크레이트 구성

```text
rmlrs-cli ──┐
bindings ───┼─> rmlrs (공개 API) ─> rmlrs-parser ─> rmlrs-model
            │                  ─> rmlrs-engine ─> rmlrs-source
            │                                  ─> rmlrs-term
            │                  ─> rmlrs-writer
conformance ┘
```

| 크레이트 | 역할 |
|---|---|
| `rmlrs-model` | RDF 항과 쿼드(인용 트리플 포함), 매핑 모델, 오류 |
| `rmlrs-parser` | Turtle·N-Quads 파서, 매핑 그래프를 모델로 변환, R2RML·이전 RML 어휘 변환(`legacy.rs`) |
| `rmlrs-term` | 템플릿, IRI 규칙과 인코딩, 자료형 리터럴, 언어 태그를 사용한 RDF 항 생성 |
| `rmlrs-source` | 입력 반복과 참조식 평가: JSONPath, CSV·CSVW 방언, XPath 3.1, SQL(PostgreSQL·MySQL·SQL Server), SPARQL 결과, 논리 뷰 행. UTF-16 디코딩, 압축 해제, HTTP(S) 다운로드(`http` 기능) |
| `rmlrs-engine` | 트리플 맵, 조인, 함수, gather map, 논리 뷰, 인용 트리플, 중복 제거를 포함한 매핑 실행 |
| `rmlrs-writer` | N-Quads 출력 및 RML-IO 논리 대상(N-Quads, N-Triples, Turtle, N3, RDF/JSON, JSON-LD, RDF/XML) |
| `rmlrs` | 위 구성 요소를 묶는 공개 API |
| `rmlrs-cli` | `rmlrs` 명령 |
| `bindings/python`, `bindings/wasm` | `rmlrs::run_in_memory`를 감싼 얇은 래퍼 |
| `conformance` | 명세 적합성 실행기(`rmlrs-conformance`) |

## 매핑 실행 과정

1. **파싱:** Turtle 매핑 문서를 읽습니다. 이전 어휘는 먼저 현재 RML로 변환합니다. 매핑 그래프를 모델로 바꾸면서 주제 맵 하나만 허용하는 규칙, 유효한 항 종류, 뷰·인용 트리플 맵의 순환 여부 등 구조를 검사합니다.
2. **컴파일:** 데이터를 읽기 전에 모든 참조 방식과 참조식(JSONPath, XPath, 열 이름, 뷰 키)을 검사·컴파일하고 함수 호출을 구현에 연결합니다. 실행할 수 없는 매핑은 이 단계에서 실패합니다.
3. **그룹화:** 같은 논리 입력을 사용하는 트리플 맵을 묶어 해당 입력을 한 번만 읽습니다.
4. **반복:** 각 그룹의 트리플 맵이 반복 단위마다 트리플을 생성합니다. CSV 행, PostgreSQL 커서 배치, MySQL 행은 점진적으로 가져옵니다. JSON 및 SQL Server 결과는 먼저 버퍼에 저장하고, XML 입력은 전체를 읽은 후 노드를 반복합니다.
5. **조인:** 다른 입력을 참조하는 객체 맵은 부모 쪽 조인 조건 값을 키로 하는 반복 인덱스를 조회합니다. 인덱스는 처음 사용할 때, 또는 데이터베이스 자식 입력을 열기 전에 만듭니다. 후자는 연결이 대기 상태로 남지 않도록 합니다.
6. **출력:** 쿼드가 생성되면 즉시 호출자에게 전달합니다. 중복 제거에는 쿼드마다 128비트(16바이트) 지문을 보관하며 쿼드 자체는 보관하지 않습니다. 단일 문서 형식인 논리 대상(RDF/JSON, JSON-LD, RDF/XML)은 예외로, 실행이 끝날 때까지 쿼드를 보관한 뒤 기록합니다.

일부 기능은 하나의 반복 단위를 넘어서는 상태가 필요합니다.

- **논리 뷰(RML-LV):** 첫 매핑 반복 전에 뷰 전체를 계산합니다. 조인에도 부모 뷰 전체가 필요합니다.
- **명명 컬렉션(RML-CC):** 여러 반복 단위에 걸쳐 커지는 컬렉션은 실행이 끝날 때까지 마지막 리스트 셀 또는 다음 컨테이너 번호를 유지합니다.
- **인용 트리플(RML-star):** 같은 반복 단위에서 인용 트리플 맵을 실행하되 결과를 즉시 출력하는 대신 캡처합니다.

## 메모리와 스트리밍

| 입력 | 읽는 방식 |
|---|---|
| CSV 및 CSVW | 필요할 때 행을 읽습니다. |
| JSON | 전체 문서를 파싱하고 선택한 반복 단위를 모읍니다. |
| XML | 전체 입력 텍스트를 읽습니다. 조건에 맞는 지역 XPath 반복은 이후 청크로 파싱하고, 다른 식은 전체 문서 트리를 사용합니다. |
| PostgreSQL | 서버 커서로 행을 배치 단위로 가져옵니다. |
| MySQL | 서버가 보내는 행을 순서대로 처리합니다. |
| SQL Server | 반복하기 전에 질의 결과를 모두 모읍니다. |
| SPARQL 결과 | CSV·TSV는 행 단위로 읽고 JSON은 전체 문서를 파싱합니다. |

원격 및 메모리 내 JSON·XML 입력은 전체 문서를 처리하는 경로를 사용합니다. 출력에서는 기본 싱크와 줄 단위 대상이 쿼드를 생성 즉시 받습니다. RDF/JSON, JSON-LD, RDF/XML 대상은 실행이 끝날 때까지 데이터를 보관합니다. 조인은 부모 반복 단위의 인덱스를 만들 수 있고, 논리 뷰는 구체화되며, 중복 제거는 서로 다른 쿼드마다 16바이트 지문을 보관합니다.

매핑은 로컬 경로, HTTP(S) 입력 및 데이터베이스 연결을 지정할 수 있고, 논리 대상은 파일을 쓸 수 있습니다. 신뢰할 수 없는 매핑에는 허용하려는 파일 시스템·네트워크 접근만 제공하세요. 자세한 내용은 [SECURITY.md](../SECURITY.md#running-mappings)에 있습니다.

## 설계 결정

순수하고 제한된 범위, 자체 매핑 파서, 입력 형식의 구현 순서, 명세 적합성 실행기, 바인딩, XPath 엔진, 내장 함수 및 HTTP 클라이언트에 관한 결정은 [docs/adr](adr)에 기록되어 있습니다.
