# Benchmarks

Performance is measured with [KROWN](https://github.com/kg-construct/KROWN),
the benchmark of the W3C Knowledge Graph Construction Community Group, using
KROWN's own execution framework, the harness the Community Group provides
for running engines on its scenarios. RMLrs is compared with
[Morph-KGC](https://github.com/morph-kgc/morph-kgc) on the same scenarios, in
the same session, with outputs checked to be identical.

## How it is measured

- **Harness.** KROWN's execution framework runs each engine in a Docker
  container and samples time, CPU and memory. RMLrs plugs in as one more
  engine (`bench/krown/rmlrs.py`) without changes to what is measured; the
  adjustments needed to run the framework on Apple Silicon are listed in
  [bench/krown/README.md](../bench/krown/README.md#what-is-changed-and-why).
- **Scenarios.** Generated by KROWN's own data generator. Its database
  scenarios exist only for PostgreSQL; the MySQL ones are the same cases
  with the database switched (`bench/krown/mysql_case.py`).
- **Runs.** 3 runs per case; tables give the range of the three, and the
  outputs of every run are compared by line count and an order-independent
  digest. A case where the engines' outputs differ is not reported as a
  speed result.
- **Quiet machine.** The collector samples the whole Docker VM, so other
  containers distort the figures. Load average and other running containers
  are logged every 30 seconds during a run; runs that overlapped other work
  are discarded.
- **Morph-KGC** 2.10.0, built for arm64 from KROWN's Dockerfile, with
  `number_of_processes = 4`. (With the framework's default of one process
  per CPU it ran out of memory on the largest inputs.)

## Environment

Apple M4 Mac (16 GB), Docker Desktop VM with 10 CPUs and 8 GB. This is not
the environment of the KROWN paper (Ubuntu 22.04, x86_64, Intel Xeon
E5-2650 v2, 48 GB). Absolute times are not comparable with published
results; the comparison between the two engines on the same machine is the
point.

## Results

### Databases · 2026-10-15

RMLrs at `e7cdd61`. No other container ran during the measurement.

| Scenario | RMLrs | Morph-KGC (4 processes) |
|---|---|---|
| PostgreSQL 14.5, 100K rows × 20 columns (2M triples) | 2.27–2.57 s | 5.07–6.24 s |
| PostgreSQL 14.5, two tables, 50% join (50K triples) | 1.13–1.56 s | 2.47–2.85 s |
| MySQL 8.0, 100K rows × 20 columns (2M triples) | 2.19–2.51 s | 5.56–6.22 s |
| MySQL 8.0, two tables, 50% join (50K triples) | 0.82–1.14 s | 2.58–3.68 s |

### Memory of the engine alone · 2026-10-14

The collector measures the whole VM, the database included. Peak resident
memory of the RMLrs process alone (`/usr/bin/time -l` on the Mac, same
tables in a local container, 3 runs, same output in every run), before and
after database rows were streamed instead of collected:

| Case | Collected first | Streamed |
|---|---|---|
| MySQL, 100K rows × 20 columns | 109–184 MB | 78–90 MB |
| MySQL, 50% join | 328–336 MB | 75–78 MB |
| MySQL, 1M rows (the 100K repeated) | 340–411 MB | 71 MB |
| PostgreSQL, 1M rows (20M triples) | 1,041–1,398 MB | 417–436 MB |

Most of what remains is the duplicate-removal set: 16 bytes per distinct
quad.

## Reproducing

```bash
git clone https://github.com/kg-construct/KROWN /path/to/KROWN   # tested at 824438c
cd /path/to/KROWN/data-generator
./exgentool generate --scenario=<scenario>.json --root=/path/to/cases   # "engine": "RMLrs" / "MorphKGC"

cd <RMLrs>
RMLRS_MORPH_PROCESSES=4 bench/krown/run.sh /path/to/KROWN /path/to/cases 3
python3 bench/krown/summary.py /path/to/cases
```

`run.sh` builds the RMLrs, Morph-KGC and database images, runs the framework
in a Linux container (its collector is Linux-only), and prints a per-case
summary: duration, CPU time, memory and an output digest. Details:
[bench/krown/README.md](../bench/krown/README.md).
